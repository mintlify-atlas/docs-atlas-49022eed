## Overview

The `@closure-next/node` package provides Node.js compatibility for Closure Next components, enabling server-side rendering (SSR) and both CommonJS and ESM module systems.

## Installation

```bash
npm install @closure-next/node
```

## Server-Side Rendering

Render Closure Next components to HTML strings on the server:

```typescript
import { renderToString } from '@closure-next/node';
import { Component } from '@closure-next/core';

class MyComponent extends Component {
  private title: string = '';

  constructor(props?: Record<string, unknown>) {
    const domHelper = new DomHelper(document);
    super(domHelper);
    if (props?.title && typeof props.title === 'string') {
      this.title = props.title;
    }
    this.createDom();
    this.enterDocument();
  }

  public override createDom(): void {
    if (!this.element) {
      super.createDom();
      const element = this.getElement();
      if (element) {
        element.setAttribute('data-testid', 'my-component');
        element.textContent = this.title;
      }
    }
  }
}

// Render to HTML string
const html = renderToString(MyComponent, {
  title: 'Hello from Server'
});

console.log(html);
// Output: <div data-testid="my-component">Hello from Server</div>
```

## Module System Compatibility

The package supports both ESM and CommonJS module systems:

<CodeGroup>

```typescript ESM
import { renderToString } from '@closure-next/node';

const html = renderToString(Component, props);
```

```javascript CommonJS
const { renderToString } = require('@closure-next/node');

const html = renderToString(Component, props);
```

```typescript Default Export
import nodeModule from '@closure-next/node';

const html = nodeModule.renderToString(Component, props);
```

</CodeGroup>

## API Reference

### renderToString()

Renders a Closure Next component to an HTML string.

```typescript
function renderToString(
  ComponentClass: new (props?: Record<string, unknown>) => Component,
  props?: Record<string, unknown>
): string
```

**Parameters:**
- `ComponentClass` - The component class constructor
- `props` - Optional properties to pass to the component

**Returns:**
- HTML string representation of the rendered component

**Example:**

```typescript
import { renderToString } from '@closure-next/node';
import { MyButton } from './components/button';

const html = renderToString(MyButton, {
  label: 'Click me',
  variant: 'primary'
});
```

## Lifecycle Management

The `renderToString` function automatically handles component lifecycle:

1. Creates a new component instance with provided props
2. Creates a temporary DOM element for rendering
3. Calls the component's `render()` method
4. Extracts the rendered HTML
5. Calls `dispose()` to clean up resources

```typescript
// Manual lifecycle (for advanced use cases)
import { Component, DomHelper } from '@closure-next/core';

const domHelper = new DomHelper(document);
const component = new MyComponent(domHelper);

const element = document.createElement('div');
await component.render(element);
const html = element.innerHTML;

component.dispose();
```

## Event Handling in Node.js

Event listeners work in Node.js environments using the DOM API:

```typescript
import { Component } from '@closure-next/core';

class EventComponent extends Component {
  constructor() {
    super();
    this.addEventListener('click', this.handleClick.bind(this));
  }

  private handleClick(event: Event): void {
    console.log('Component clicked!');
  }
}

// In Node.js
const component = new EventComponent();
const element = component.getElement();

if (element) {
  const event = new Event('click');
  element.dispatchEvent(event);
}
```

## Integration Examples

### Express.js

```typescript
import express from 'express';
import { renderToString } from '@closure-next/node';
import { MyComponent } from './components';

const app = express();

app.get('/', (req, res) => {
  const html = renderToString(MyComponent, {
    title: 'Welcome to Closure Next'
  });

  res.send(`
    <!DOCTYPE html>
    <html>
      <head>
        <title>Closure Next App</title>
      </head>
      <body>
        <div id="app">${html}</div>
        <script src="/bundle.js"></script>
      </body>
    </html>
  `);
});

app.listen(3000);
```

### Next.js

```typescript
import { renderToString } from '@closure-next/node';
import { MyComponent } from '@/components';

export default function Page() {
  const html = renderToString(MyComponent, {
    message: 'Server-rendered content'
  });

  return (
    <div dangerouslySetInnerHTML={{ __html: html }} />
  );
}
```

### Fastify

```typescript
import Fastify from 'fastify';
import { renderToString } from '@closure-next/node';
import { AppComponent } from './components';

const fastify = Fastify();

fastify.get('/', async (request, reply) => {
  const html = renderToString(AppComponent, {
    user: request.query.user || 'Guest'
  });

  reply.type('text/html').send(`
    <!DOCTYPE html>
    <html>
      <body>${html}</body>
    </html>
  `);
});

fastify.listen({ port: 3000 });
```

## Best Practices

<AccordionGroup>
  <Accordion title="Always dispose components after SSR">
    The `renderToString` function automatically calls `dispose()`, but if you're manually managing component lifecycle, always clean up:

    ```typescript
    const component = new MyComponent();
    try {
      const html = await component.render(element);
      // Use html...
    } finally {
      component.dispose();
    }
    ```
  </Accordion>

  <Accordion title="Handle props safely">
    Always validate and type-check props in your component constructors:

    ```typescript
    constructor(props?: Record<string, unknown>) {
      super();
      if (props?.title && typeof props.title === 'string') {
        this.title = props.title;
      }
    }
    ```
  </Accordion>

  <Accordion title="Use ESM imports for better tree-shaking">
    Prefer ESM imports over CommonJS for better bundle optimization:

    ```typescript
    // Preferred
    import { renderToString } from '@closure-next/node';

    // Avoid (unless required for compatibility)
    const { renderToString } = require('@closure-next/node');
    ```
  </Accordion>
</AccordionGroup>

## Testing

The package includes comprehensive tests for Node.js environments:

```typescript
import { renderToString } from '@closure-next/node';
import { MyComponent } from './components';

describe('SSR Tests', () => {
  test('should render component to string', () => {
    const html = renderToString(MyComponent);
    expect(html).toContain('data-testid="my-component"');
  });

  test('should handle props', () => {
    const html = renderToString(MyComponent, {
      title: 'Test Title'
    });
    expect(html).toContain('data-title="Test Title"');
  });

  test('should clean up after rendering', () => {
    const disposeSpy = jest.spyOn(MyComponent.prototype, 'dispose');
    renderToString(MyComponent);
    expect(disposeSpy).toHaveBeenCalled();
  });
});
```

## Limitations

<Warning>
  Server-side rendering has some limitations:
  - Browser-specific APIs (like `localStorage`, `sessionStorage`) are not available
  - Window and document objects are provided by jsdom in test environments
  - Event handlers won't execute during SSR (only hydration on the client)
</Warning>
